# 数据分析类报告规范

适用于：经营分析、月报 / 季报 / 年报、指标通报、专题分析、对标排名、经营复盘。

完整示例：`examples/demo_data_analysis.py`（预览图在 `examples/preview/data-analysis-*.png`）。

---

## 1. 金字塔沟通：结论先行

通用方法（金字塔四原则、SCQA、故事线搭建、逻辑关系选择）见 [pyramid-logic.md](pyramid-logic.md)。本节只写数据分析类的特有做法。

### 1.1 整份报告

```
封面 → 核心结论页 → 目录 → 章节1（概览）→ 章节2（问题诊断）→ 章节3（举措建议）→ 结束页
```

- **核心结论页就是塔尖**：只看这一页，读者也应知道「结果怎么样、原因是什么、下一步做什么」。
  内容是 3±1 条结论，每条 = 判断句 + 关键数字，用 `pg.conclusions(items)` 生成（参见示例第 2 页）。
- **按内容页数调整结构**：是否单设核心结论页、何时放目录，以 [pyramid-logic.md](pyramid-logic.md) §3「整份报告的结构」为准。
- 章节之间不重叠、不遗漏（MECE）。常见切分方式：
  - 现状 → 问题 → 举措
  - 收入 → 用户 → 业务 → 渠道
  - 全市 → 区县 → 网格
- 开场需要铺垫时可用 SCQA：背景（S）→ 冲突（C）→ 问题（Q）→ 答案（A）。答案就是核心结论。

### 1.2 每一页

| 位置 | 内容 | 方法 |
|---|---|---|
| 标题 | 章节序号 + 主题，20 字以内，可带简短判断：「一、经营概览：收入稳中有进」 | `deck.page()` |
| 结论条 | **一句话结论**，最多 2 行，必须包含关键数字并着色。这是本页的 so what | `pg.lead()` |
| 主体 | 2–4 个支撑论点，彼此不重叠，合起来能推出结论；每个论点 = 判断 + 数据证据 | 图表 / 表格 / 指标卡 / 议题树 |
| 页脚 | 数据来源、统计口径、时间范围 | `pg.source()` |

**自检**：只看标题和结论条，能否知道本页结论？遮住结论条只看主体，能否推出同样的结论？两个问题都要回答「能」。

### 1.3 结论句写法

- ✅「1-9月收入同比 **+4.8%**、领先全省 **+0.9pp**，但完成率落后时序 **−1.9pp**」：判断 + 数字 + 比较基准
- ❌「收入情况分析」：只有主题，没有结论
- ❌「收入表现良好」：既没有数字，也没有比较基准

每个关键数字都要有比较基准：同比、环比、目标、时序进度、全省或兄弟单位均值、排名。

## 2. 重点数字着色：做得好标红，做得差标绿

| 含义 | 颜色 | 标记 | 生成方式 |
|---|---|---|---|
| 做得好 | 红 `#C00000` RGB(192,0,0) | `<good>…</good>` | `delta / pp / growth / vs_target` 自动判断 |
| 做得差 | 绿 `#008650` RGB(0,134,80) | `<bad>…</bad>` | 同上 |
| 中性重点 | 黑色加粗 | `<b>…</b>` | 手写 |

规则：

1. **按好坏着色，不按涨跌着色**。离网率、投诉率、成本、欠费、拆机这类「越低越好」的指标，下降就是好，要标红。调用时传 `better="down"`：
   `growth(1.64, 1.38, better="down")` → 绿色 `+18.8%`（拆机量上升，是坏事）
2. **叙述文字里只标关键数字**：结论条、要点、结论框这类叙述文字，每页着色不超过约 6 处。规模、基数等中性数字用黑色或加粗，不着色。
   指标卡的变化值、表格的变化列属于结构化数据，按规则全部着色，**不计入**这个上限。
   着色过多时，先把次要数字（例如已经有同比时的环比、补充说明里的数字）改成 `better=None`，只加粗不着色。
3. **同一个数字，全篇同色**：同一个指标值在不同页面（核心结论页、分析页、表格）出现时，颜色必须一致。做法是只计算一次、存成变量，各处复用同一个 `growth()/pp()` 的结果。
4. **好坏要有基准**：着色的依据（目标、时序进度、同期、均值）要在句子里或表头中写明。
   下级单位（区县、网格、渠道）默认与上级整体（全市、全区）比较，表头写明「较全区」等字样。
5. **数据分析页里，红色只表示「好」**。强调中性内容用加粗，不要用 `<red>`。母版的结构红（标题线、项目符号、表头、标题条）不受此限制。
6. **图表**：单系列默认用浅灰色，只给要强调的类别着色：`highlight={"9月": "good", "F县": "bad"}`。排名图中领先者标红、落后者标绿。
   重要但不评好坏的柱子（目标值、测算值，例如「四季度月均需」）用 `"neutral"`（深灰）。
7. **表格**：变化列一律用 `growth / pp / delta` 生成；合计行用 `highlight_rows=[末行], highlight_fill=LIGHT` 并加粗。
8. **指标卡**：大数字用 `num()` 生成，默认黑色，颜色交给下方的变化值。
   只有大数字本身就是评价时才设 `judge`，例如完成率对比时序进度、达标率、排名。渗透率、收入、用户数这类水平值不设 judge。

## 3. pp 规则（百分点）

| 指标类型 | 变化的表示方式 | 例子 |
|---|---|---|
| **比率类**：渗透率、占比、份额、转化率、完成率、离网率、毛利率、增速本身 | 两数相减，单位 **pp** | 渗透率 32.1% → 35.4%：写「+3.3pp」，不写「+10.3%」 |
| **绝对量**：收入、用户数、ARPU、DOU、业务量 | 变化率，单位 **%** | 收入 11.98 → 12.60 亿元：写「+5.2%」 |

常见场景：

- 增速对比：本期增速 4.8%，全省 3.9% → 「领先全省 **+0.9pp**」→ `pp(4.8, 3.9)`
- 完成率对比时序进度：73.1% vs 75% → 「落后时序 **−1.9pp**」→ `pp(73.1, 75)`
- 增速变化：今年增速 4.8%，去年 3.7% → 「增速提升 **+1.1pp**」

格式要求：
- 计算得出的值保留 1 位小数，变化值始终带符号（`+` / `−`）。四舍五入后为 0 的变化显示为不带符号的「0.0」，只加粗不着色（视为持平）。
- 同一页内同类指标的单位和精度尽量一致，但**不能为了统一精度而编造小数位**：源数据给的是整数（如 41%）时，按源数据原样展示。
- 纯数字（指标卡大数字、表格数值）用 `num(v, unit)`，不要用 f-string 自己拼正负号。

函数分工：

| 场景 | 用法 | 输出 |
|---|---|---|
| 绝对量变化 | `growth(new, old)` | `+5.2%`（着色） |
| 比率之差 | `pp(new, old)` | `−1.3pp`（着色） |
| 已知变化值 | `delta(v, "pp")` / `delta(v, "%")` | 着色 |
| 展示「完成率与时序进度的差距」 | `pp(完成率, 时序进度)` | `−1.9pp`（着色） |
| 给「实际值本身」按是否达标着色 | `vs_target(完成率, 时序进度, unit="%")` | `73.1%`（着色），常用于表格单元格 |
| 不判断好坏的数字 | `num(v, unit)` / `delta(v, better=None)` | 黑色 / 加粗 |

### 常用口径（材料没有另外说明时采用，并写进 `source()`）

- **时序进度**：按月统计时 = 已过月数 ÷ 12（9 月末为 75.0%）；按日统计时 = 已过天数 ÷ 全年天数。
- **剩余月均需完成** = (全年目标 − 累计完成) ÷ 剩余月数；与已过月份月均对比时用 `growth()`，并以 `better=None` 展示（这是要求，不是成绩）。
- **完成率** = 累计完成 ÷ 全年目标。完成率对比时序进度：高于或等于为好，低于为差。

## 4. 逻辑严谨

- **派生数字一律用代码算**：合计、同比、占比、pp 差、完成率、缺口都从原始数据计算，不手算、不心算。
- **用 assert 做勾稽校验**：分项之和 = 合计；归因之和 = 总变化；占比之和 = 100%。示例脚本开头有写法可参考。
- **口径一致**：同一页内的数字，统计周期和口径必须一致；口径不同的数字不能直接比较，必须比较时要注明。
- **区分事实与判断**：数据说明「是什么」；归因必须有证据；相关不等于因果。推测性的判断要用「初步判断」「可能」等措辞。
- **不编造**：缺少数据时，写定性判断或缩减对应模块，并在交付时列出数据缺口。不要在页面上留「待补充」字样。
- **假设要交代**：口径、统计周期、比较基准是你自己假设的，要写进 `source()`，并在交付时告诉用户。
- **图表要诚实**：柱状图纵轴从 0 开始（库已自动处理）；不截断坐标轴；双轴图慎用；百分比柱和绝对量柱不要混在同一坐标轴上。

## 5. 常用页型

| 页型 | 什么时候用 | 版面要点 | 示例 |
|---|---|---|---|
| **核心结论页** | 报告开篇，给出整体结论 | 结论条 + `pg.conclusions(items)`：3 行「序号徽标 / 判断标题 + 证据句 / 右侧关键数字」 | 第 2 页 |
| **指标总览页** | 汇报整体经营情况 | 结论条 → 一排 4 张指标卡 → 左侧趋势图（3 份宽）+ 右侧关键发现（2 份宽） | 第 4 页 |
| **对标 / 排名页** | 区县、渠道、产品之间对比 | 左侧表格（7 份宽，变化列着色，合计行灰底）+ 右侧 2–3 个结论框（领跑 / 追赶 / 关注） | 第 5 页 |
| **问题诊断页** | 解释某个指标为什么变化 | `cause_tree()`：问题框 → 原因拆解（标出贡献度，首要原因红框突出）→ 数据证据，底部一条「启示」；原因有先后传导关系时改用 `causal_chain()` | 第 7 页 |
| **举措计划页** | 给出下一步行动 | 表格：主线 / 关键举措 / 量化目标 / 牵头部门 / 完成时间；底部用阶段链展示推进节奏 | 第 9 页 |
| **图表 + 洞察页** | 单一主题的深入分析 | `cols([3, 2])`：左侧图表，右侧 `bullets()` 写 3 条「<b>短判断：</b>证据」 | 第 4 页下半部分 |

选择图表：

- 趋势：柱状图（离散月份）或折线图（连续走势、多系列对比）
- 构成：环形图（不超过 5 类）或堆积柱状图
- 排名：横向条形图 `bar(..., horizontal=True)`，按数值排序
- 精确数值较多时，用表格而不是图表

## 6. 交付前自检

- [ ] 核心结论页的结论，和各章节的 lead 结论一致，没有矛盾
- [ ] 每页都有一句话结论，并且包含带基准的数字
- [ ] 着色按「好坏」判断；「越低越好」的指标传了 `better="down"`
- [ ] 同一个数字在不同页面的颜色一致；叙述文字中的着色没有过多
- [ ] 比率类指标的变化用的是 pp，绝对量的变化用的是 %
- [ ] 派生数字全部由代码计算，勾稽关系有 assert 校验
- [ ] 每页页脚写了来源和口径
- [ ] 没有沿用示例里的数据
